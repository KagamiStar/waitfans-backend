# Waitfans 数据库数据归属

本文档是 Waitfans 持久化数据的归属清单。新增表、迁移数据、备份和恢复时，以本文档与 `database/sharded-layout.sql` 为准。

## 设计原则

- `waitfans` 只保存账号、互动、消息、分类等全站核心数据。
- 首页轮播图单独存放在 `waitfans_carousel`，不与用户、视频或互动数据共库。
- 每个视频主分区使用一个独立数据库；视频元数据和视频统计必须位于同一个分区库。
- 视频文件和封面文件不写入 MySQL。文件存入 MinIO 或 OSS，分区库只保存对象地址。
- 全局视频 ID 由 `waitfans.video_locator` 分配。该表只保存路由和聚合所需字段，不保存标题、简介、封面或视频地址。
- 旧代码可以通过 `waitfans.video` 和 `waitfans.video_stats` 两个只读视图跨分区查询。禁止对这两个视图执行写操作；写操作必须经过 `PartitionedVideoStore`。

## 视频读写链路

1. 投稿完成后，`PartitionedVideoStore` 在 `waitfans.video_locator` 生成全局 `vid`。
2. 根据投稿的 `mc_id` 选择 `waitfans_video_<mc_id>`。
3. 在同一事务中写入该库的 `video` 和 `video_stats`。
4. 审核状态和播放、点赞、收藏等统计更新先通过 `video_locator` 定位分区，再更新目标分区库。
5. 跨分区推荐、搜索结果回表和管理端统计通过核心库只读联合视图查询。

## 首页轮播图链路

`GET /carousel/list` 只查询 `waitfans_carousel.carousel`。前端轮播图不再截取推荐视频前五条，也不再以静态 JSON 作为权威数据源。

轮播图图片可以是前端公开资源路径或对象存储 URL；数据库中只保存地址，不保存图片二进制。

## 视频文件与播放

- 原文件位于 MinIO/OSS；数据库字段 `video.video_url` 保存对象地址。
- 用户端和管理端播放器统一访问 `GET /media/video/{vid}`。
- 后端从正确分区读取视频记录，再代理对象存储内容，并支持 `Range`、`206 Partial Content`、`Content-Range` 和 `Accept-Ranges`。
- 这样浏览器不再依赖 MinIO bucket 的公开权限、CORS 或部署机器上的 `127.0.0.1` 地址，可以稳定拖动进度条并验证播放统计。

## 初始化与迁移

新环境：

```powershell
.\scripts\setup-local-mysql.ps1
```

复用已有本地数据库时，脚本会检测 `waitfans.video` 是否仍为基础表；若是，则执行一次迁移。迁移过程会：

1. 创建轮播图库和 19 个视频分区库；
2. 把旧 `video`、`video_stats` 数据按 `mc_id` 复制到对应分区库；
3. 创建 `video_locator`；
4. 用只读联合视图替换旧视频表；
5. 确认复制完成后删除迁移临时表。

手动初始化使用：

```powershell
.\scripts\initialize-database.ps1
```

`-Force` 会删除并重建上述全部 Waitfans 管理数据库，只能在明确需要清空本地数据时使用。

初始化完成且 MinIO 已启动后，可写入幂等的本地播放验证数据：

```powershell
.\scripts\seed-playback-demo.ps1
```

脚本使用仓库自带的示例 MP4，上传到本地 MinIO，并在音乐分区库创建一条已过审视频。脚本会输出可直接访问的视频详情页地址；如果后端已经运行，重启一次以刷新推荐缓存。

## 运维检查

确认视频没有落回核心库：

```sql
SELECT TABLE_TYPE
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = 'waitfans' AND TABLE_NAME IN ('video', 'video_stats');
```

两行都应为 `VIEW`。

确认每个视频只存在于一个分区：

```sql
SELECT COUNT(*) AS view_count,
       (SELECT COUNT(*) FROM waitfans.video_locator) AS locator_count
FROM waitfans.video;
```

两者应相等。备份时必须同时备份 `waitfans`、`waitfans_carousel` 和全部 `waitfans_video_*` 数据库。

## 新增主分区检查清单

新增 `mc_id` 时必须同时完成：

1. 创建 `waitfans_video_<mc_id>` 数据库及 `video`、`video_stats` 表；
2. 把新库加入 `waitfans.video` 和 `waitfans.video_stats` 联合视图；
3. 把 `mc_id` 加入 `VideoShardCatalog`；
4. 更新初始化脚本、Docker 授权脚本和本文档；
5. 验证投稿、审核、播放、统计更新和跨分区查询。
